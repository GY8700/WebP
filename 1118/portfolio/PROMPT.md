# 개인 포트폴리오 웹사이트(Myfolio) 제작 프롬프트

> **제출용 안내:** 이 문서는 실제 제작 과정에서 대화로 나누어 전달한 요구사항과 완성된 사이트의 구현 내용을 바탕으로 정리한 **통합·재구성 프롬프트**입니다. 최초에 한 번 입력했던 원문을 그대로 복원한 기록은 아닙니다.

## AI에 입력할 통합 제작 프롬프트

당신은 웹 접근성, 반응형 웹 디자인, 프론트엔드 개발에 능숙한 웹 개발자입니다. 대학교 **웹프로그래밍 수업 과제**로 제출할 개인 포트폴리오 웹사이트를 제작해 주세요. 결과물은 단순한 디자인 시안이 아니라 실제 브라우저에서 열어서 사용할 수 있는 완성된 정적 웹사이트여야 합니다.

### 1. 제작 목적 및 기본 조건

- 사이트 이름은 **Myfolio**, 영문 페이지 제목은 `Myfolio — Personal Portfolio`로 합니다.
- 소프트웨어공학을 공부하는 대학생의 개인 웹사이트로, 자기소개, 현재 공부하는 기술, 관심 분야, 학습 과정과 목표, 연락 방법을 보여줍니다.
- **진행 중인 프로젝트, 미완성 프로젝트, 실제로 완성하지 않은 결과물을 프로젝트 사례처럼 소개하는 섹션은 만들지 마세요.** 일반적인 Projects 섹션도 제외합니다.
- 전체 사이트는 **한국어 중심**으로 작성하되, `ABOUT ME`, `SKILLS & TOOLS`와 같은 짧은 영문 보조 제목은 허용합니다.
- 개인 이름, 학력의 구체적 연도, 이메일, GitHub 주소, 기술 숙련도 등 제공되지 않은 사실을 임의로 꾸미지 마세요. 소개 문구는 나중에 수정할 수 있는 예시로 만들고, 연락처는 명확한 플레이스홀더를 둡니다.
- 프론트엔드 기술 학습 내용을 보여주는 **하나의 긴 페이지(원페이지 포트폴리오)**로 만듭니다.

### 2. 개발 기술 및 실행 환경

- **HTML5, CSS3, 바닐라 JavaScript**만 사용합니다.
- React, Vue, Next.js, TypeScript, npm, 빌드 도구, 백엔드, 데이터베이스 등을 사용하지 마세요.
- 외부 CDN, 외부 이미지, 외부 폰트 또는 외부 아이콘 라이브러리에 의존하지 마세요. 필요한 아이콘은 인라인 SVG나 CSS로 구현합니다.
- `index.html` 파일을 더블클릭하여 로컬 브라우저에서 실행할 수 있어야 합니다.
- 상대 경로로 CSS/JavaScript를 연결하여 GitHub Pages의 프로젝트 사이트(`https://사용자명.github.io/portfolio/`)에서도 정상 동작해야 합니다.

### 3. 전체 디자인 콘셉트

- 밝고 미니멀하며 현대적인 디자인으로 구현합니다. 화면이 답답하지 않도록 충분한 여백을 사용합니다.
- 기본 배경은 흰색 `#FFFFFF`, 보조 배경은 옅은 블루그레이 `#F8FAFF`, 텍스트는 짙은 네이비 계열, 강조 색상은 블루 `#3665EB`를 사용합니다. 컬러 값은 CSS 사용자 정의 변수로 관리합니다.
- 카드에는 은은한 테두리, 부드러운 그림자, 약간 둥근 모서리를 사용합니다.
- 섹션 제목은 크고 명확하게, 설명 문장은 읽기 쉬운 크기로 구성합니다.
- 스크롤·호버 애니메이션은 자연스럽고 절제된 수준으로 적용합니다. 지나친 시각 효과는 피합니다.
- PC에서는 콘텐츠 영역을 중앙 정렬하고, 태블릿과 모바일에서는 레이아웃이 유연하게 바뀌게 해 주세요.
- 상단에 고정형 또는 스크롤 시 유지되는 내비게이션을 두어 이동을 쉽게 합니다.

### 4. 페이지 구성 및 섹션별 상세 요구사항

**① Home / 메인 화면**
- 왼쪽에는 소개 문구, 오른쪽에는 **코드를 표현한 장식용 에디터 카드**를 배치합니다. 모바일에서는 위아래로 배치합니다.
- 메인 제목은 **“작은 아이디어에서 좋은 경험으로.”**처럼 간결하고 인상적인 문구로 작성합니다.
- 소프트웨어공학을 공부하는 학생이라는 사실을 소개하고, `저에 대해 알아보기`, `연락처 보기` 버튼을 제공합니다.
- 코드 카드에는 `about-me.js`라는 제목과 전공·관심 분야·학습 태도를 나타내는 짧은 예시 JavaScript 코드를 시각적으로 표현합니다. 이는 장식 요소이며 실제 사용자 데이터라고 주장하지 마세요.

**② About Me / 자기소개**
- 전공과 학습 태도를 소개하는 자연스러운 한국어 문단을 작성합니다.
- `호기심`, `꾸준한 학습`, `사용자 관점`과 같은 키워드를 카드로 보여줍니다.
- 긴 자기소개를 나열하기보다는 핵심 가치가 빠르게 읽히도록 구성합니다.

**③ Skills & Tools / 기술 스택**
- `HTML5`, `CSS3`, `JavaScript`, `Java`, `Git`, `VS Code` 카드 6개를 표시합니다.
- 카드마다 기술명, 분류, 한 줄 소개를 넣습니다. 사용 경험을 과장하거나 숙련도 수치를 임의로 만들지 마세요.
- 분류 버튼은 **전체 / Frontend / Programming / Tools** 네 가지로 만들고, 클릭하면 해당 카드만 보이도록 JavaScript로 처리합니다.
- 선택된 필터 버튼이 시각적으로 구분되어야 하며 접근성 상태(`aria-pressed`)도 갱신해 주세요.

**④ Interests / 관심 분야**
- `Web Development`, `UI / UX Design`, `New Technology` 세 가지 카드로 구성합니다.
- 각 카드에는 인라인 SVG 또는 CSS 일러스트, 관심 분야 이름, 한두 문장의 설명을 넣습니다.
- 사용자가 어떤 분야에 흥미를 느끼는지를 설명하되, 실제 진행 중인 프로젝트 이름은 언급하지 않습니다.

**⑤ My Journey / 성장 기록**
- **NOW → NEXT → GOAL** 형태의 세 단계 타임라인을 만듭니다.
- NOW는 프로그래밍 및 웹 기초 학습, NEXT는 작은 기능을 구현하는 경험, GOAL은 사용자 문제를 해결하는 개발자로의 성장을 설명합니다.
- 정확한 연도나 성취 내용을 임의로 만들어 넣지 마세요.

**⑥ Contact / 연락처**
- 이메일 복사 버튼과 GitHub 프로필 이동 버튼을 제공합니다.
- 사용자 정보가 아직 없다면 `yourname@example.com`과 비어 있는 GitHub 설정값을 사용하고, 임의의 실제 주소를 생성하지 마세요.
- 이메일이 예시 주소인 동안에는 복사 성공을 가장하지 말고 수정 안내 메시지를 표시합니다.
- GitHub 링크가 설정되지 않았다면 잘못된 페이지로 이동시키지 말고 설정 안내를 표시합니다.
- 하단에는 저작권 문구, 자동 갱신되는 연도, 맨 위로 이동 링크를 배치합니다.

### 5. JavaScript로 반드시 구현할 기능

1. **라이트/다크 테마 전환:** 버튼 클릭 시 테마가 바뀌고, `localStorage`에 선택값을 저장하여 새로고침 후에도 유지합니다. CSS 변수로 두 테마를 구현합니다.
2. **반응형 모바일 메뉴:** 좁은 화면에서는 메뉴 버튼이 나타나고, 클릭하면 내비게이션이 열리고 닫혀야 합니다. 메뉴 항목 선택 또는 `Escape` 키 입력 시 닫히도록 합니다.
3. **섹션 이동 및 활성 메뉴 표시:** 내비게이션 링크는 해당 섹션으로 부드럽게 스크롤하고, 현재 읽고 있는 섹션에 맞춰 메뉴 강조 상태를 변경합니다.
4. **기술 스택 필터:** `data-category`와 `data-filter` 속성을 활용하여 분류별 카드 표시 여부를 제어합니다.
5. **스크롤 애니메이션:** `IntersectionObserver`로 섹션과 카드가 자연스럽게 등장하도록 합니다. `prefers-reduced-motion` 설정이 활성화되어 있으면 과한 동작을 생략합니다.
6. **스크롤 진행도 표시:** 화면 최상단에 읽은 페이지 비율을 보여주는 얇은 진행 막대를 구현합니다.
7. **이메일 복사 및 토스트 알림:** `navigator.clipboard`를 우선 사용하고, 사용할 수 없는 환경에서는 대체 처리 또는 명확한 실패 안내를 제공합니다. 예시 이메일에 대해서는 실제 복사 완료로 안내하지 않습니다.
8. **연도 자동 출력:** JavaScript의 현재 연도를 사용하여 푸터 저작권 문구를 갱신합니다.

### 6. 반응형 웹·접근성·품질 기준

- 데스크톱, 태블릿, 스마트폰에서 레이아웃과 글자가 자연스럽게 조정되도록 CSS Grid, Flexbox, 미디어 쿼리를 사용합니다.
- 모바일에서 불필요한 가로 스크롤이 생기지 않게 합니다.
- `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>` 등 시맨틱 태그를 적극 활용합니다.
- 헤딩 순서, 키보드 포커스, 버튼의 접근 가능한 이름, `aria-expanded`, `aria-pressed`, 상태 알림(`aria-live`)을 고려합니다.
- `본문으로 바로가기` 링크를 제공하고, 시각적 대비와 읽기 쉬운 행간을 확보합니다.
- 클릭 불가능한 요소가 버튼처럼 보이지 않도록 하고, 링크나 버튼은 실제 동작해야 합니다.
- 한국어 오탈자, HTML 태그 닫힘, CSS/JS 파일 경로, JavaScript 구문 오류, 모바일 메뉴·필터·테마 기능을 확인합니다.
- 실제로 실행하거나 확인하지 않은 테스트는 통과했다고 주장하지 마세요.

### 7. 산출물 형식

아래의 폴더 구조로 **실행 가능한 전체 파일**을 만들어 주세요.

```text
portfolio-website/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── main.js
└── README.md
```

- `index.html`에 사이트 전체 구조와 각 섹션 내용을 작성합니다.
- `css/style.css`에 테마 변수, 데스크톱/모바일 레이아웃, 카드, 버튼, 애니메이션, 반응형 규칙을 작성합니다.
- `js/main.js`에 상호작용을 구현하고, **이메일/GitHub 주소를 쉽게 수정할 수 있는 설정 객체**를 파일 상단에 둡니다.
- `README.md`에 사이트 개요, 기술 스택, 주요 기능, 실행 방법, 연락처 수정 위치, GitHub Pages 배포 방법을 설명합니다.
- 전체 디자인은 밝고 미니멀한 스타일을 기본으로 유지하며, **미완성 프로젝트 소개는 넣지 않습니다.**

### 8. 완료 전 확인 사항

최종 결과를 제공하기 전, 다음 사항을 검토해 주세요.

- `index.html`을 열었을 때 스타일과 스크립트가 상대 경로로 연결되는가?
- 6개 섹션(Home/About/Skills/Interests/Journey/Contact)이 존재하며 내비게이션으로 이동할 수 있는가?
- 라이트/다크 테마, 기술 분류 필터, 모바일 메뉴, 스크롤 애니메이션, 이메일 안내가 구현되어 있는가?
- 프로젝트 소개 섹션이나 실제로 하지 않은 개발 성과를 꾸며낸 내용은 없는가?
- 화면 크기가 달라져도 콘텐츠가 읽기 쉽고 버튼이 사용 가능한가?
- GitHub Pages에 소스코드를 업로드하면 별도의 빌드 과정 없이 배포 가능한가?

단순한 설명이나 코드 일부만 제시하지 말고, **바로 실행하고 수정할 수 있는 완성된 코드와 파일 구조**를 제공해 주세요.
